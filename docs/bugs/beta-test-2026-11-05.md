# GastosGo Beta Test Report
**Date:** 2026-11-05
**Tester:** Mobile Beta Tester Agent (second pass)
**Build:** v1.0.0 (initial commit ba87090)
**Platform:** iOS + Android (React Native / Expo 52)
**Method:** Static analysis — full source read of all screens, hooks, DB layer, and utilities
**Scope:** All onboarding screens, all tabs, both modals, lock screen, settings, and data layer

---

## Summary

| Severity | Count |
|----------|-------|
| Critical | 5 |
| High     | 8 |
| Medium   | 7 |
| Low      | 5 |
| **Total**| **25** |

**Overall stability:** Beta-quality. The Drizzle/SQLite DB layer is real code but the userId mismatch (BUG-05) means the entire data layer effectively returns empty results for every user. The PIN flow has a length contract break that locks every user out permanently. These two issues alone make the app non-shippable.

**Priority fixes (in order):**
1. BUG-05 — userId mismatch kills all data reads
2. BUG-02 — PIN length mismatch locks every user out permanently
3. BUG-01 — cold-start redirect race (crash/blank screen)
4. BUG-16 — default categories invisible to budget queries
5. BUG-07 — recurring payment method silently dropped

## Critical

**Bug ID:** BUG-01
**Severity:** Critical
**Title:** Cold-start PIN redirect fires before navigation is ready — potential redirect loop or blank screen
**Platform:** iOS + Android
**Build:** v1.0.0
**Steps to Reproduce:**
1. Set a PIN via onboarding.
2. Force-kill and reopen the app.
**Expected Behavior:** App redirects once to `/lock`; user unlocks and lands on `/(tabs)`.
**Actual Behavior:** `useEffect` in `app/_layout.tsx` calls `router.replace('/lock')` during the very first render, before the navigator has mounted its full stack. The `pathname` check races with router state — on some devices the redirect fires twice (pathname is still `/` for a tick), producing a redirect loop or blank white screen.
**Frequency:** Intermittent — more likely on slow Android devices.
**Logs/Evidence:**
- `app/_layout.tsx` lines 30–39: `pathname` intentionally excluded from deps; `router.replace` called without a readiness guard.
- Expo Router v4 requires the navigation container to be fully mounted before `router.replace` is safe.
**Suggested Investigation Area:** Wrap the redirect in a `useRootNavigationState` check or defer via `router.isReady`.

**Bug ID:** BUG-02
**Severity:** Critical
**Title:** PIN length contract mismatch — onboarding stores a 6-digit hash; lock screen submits at 4 digits — permanent lockout
**Platform:** iOS + Android
**Build:** v1.0.0
**Steps to Reproduce:**
1. Complete onboarding. PIN Setup screen auto-advances at 6 digits and stores the 6-digit hash.
2. Exit app. Reopen — lock screen appears.
3. Enter the first 4 digits of your PIN.
**Expected Behavior:** Lock screen waits for all 6 digits before submitting.
**Actual Behavior:** `app/lock.tsx` line 140: `if (current.length < 4) return;` — submits at 4 digits, hashes a 4-digit prefix, compares against the 6-digit hash. Never matches. Every user is locked out permanently after first setup.
**Frequency:** Always.
**Logs/Evidence:**
- `app/lock.tsx` line 140 (`< 4`) vs `app/onboarding/pin-setup.tsx` line 27 (`=== 6`).
- Hint in `lock.tsx` line 230 says "4–6 digit PIN" but setup forces exactly 6.
**Suggested Investigation Area:** Change `lock.tsx` line 140 to `if (current.length < 6) return;` and remove the misleading hint text, or introduce a configurable PIN_LENGTH constant shared by both files.

**Bug ID:** BUG-05
**Severity:** Critical
**Title:** `USER_ID = 'stub-user-001'` in all hooks never matches `userId = 'local-user'` written by DB layer — all data reads return empty
**Platform:** iOS + Android
**Build:** v1.0.0
**Steps to Reproduce:**
1. Add an expense.
2. Navigate to Expenses, Budgets, or Insights tab.
**Expected Behavior:** Expense appears in every relevant list and chart.
**Actual Behavior:** `insertExpense` (and `insertRecurringRule`) call `getProfile()?.userId` which returns `'local-user'` (set in `insertProfile`). Every read query (`getExpensesByMonth`, `getBudgetProgress`, `getRecurringRules`, `getMonthlyExpenseSummary`, `getSavingsGap`) filters by `USER_ID = 'stub-user-001'`. The two values never match — all lists are permanently empty after any insert.
**Frequency:** Always — affects all tabs and all data.
**Logs/Evidence:**
- `hooks/useExpenses.ts` line 12, `hooks/useBudgets.ts` line 4, `hooks/useRecurring.ts` line 14, `hooks/useSavings.ts` line 4, `app/(tabs)/insights.tsx` line 17: all `'stub-user-001'`.
- `lib/db/stubs.ts` line 72: `userId = 'local-user'` in `insertProfile`.
**Suggested Investigation Area:** Export a single `LOCAL_USER_ID = 'local-user'` constant from `lib/db/stubs.ts` and import it into all hooks. Or change `insertProfile` to use `'stub-user-001'`.

**Bug ID:** BUG-22
**Severity:** High
**Title:** `formatDate` in `utils/format.ts` uses `new Date(isoDate)` which parses ISO date strings as UTC midnight — "Today" / "Yesterday" labels wrong for PST users
**Platform:** iOS + Android
**Build:** v1.0.0
**Steps to Reproduce:**
1. Add an expense dated today (PST/UTC+8).
2. View it on the Expenses screen or Dashboard.
**Expected Behavior:** Row shows "Today".
**Actual Behavior:** `formatDate` creates `new Date('2026-11-05')` — JavaScript parses this as UTC midnight 2026-11-05T00:00:00Z. The local date in UTC+8 is 2026-11-05T08:00:00+08:00. The comparison `isoDate === today.toISOString().split('T')[0]` compares the stored ISO string against today's UTC date, which works until midnight UTC (8am PST). For the first 8 hours of each PST day, expenses logged "today" show as the previous date string rather than "Today".
**Frequency:** Always between 00:00–07:59 PST (midnight–8am local).
**Logs/Evidence:** `utils/format.ts` lines 29–38.
**Suggested Investigation Area:** Compare using local-time date strings: `const todayLocal = new Date().toLocaleDateString('sv');` and compare against `isoDate` directly.

**Bug ID:** BUG-25

**Title:** `getMultiMonthSummary` key format `${year}-${month}` (without zero-padding) will silently miss months 1–9 if ever adopted
**Platform:** iOS + Android
**Build:** v1.0.0

**Suggested Investigation Area:** Pre-emptively use zero-padded month in both the key builder and the lookup, or switch to a `${year}-${String(month).padStart(2, '0')}` format consistently.

## Test Coverage Gaps (not bugs — flagged for follow-up)

1. **No Android back-navigation guard on onboarding** — pressing the hardware back button at any step exits the flow mid-way, leaving a partial profile row.
2. **Dark mode has no effect** — `GluestackUIProvider colorMode={effectiveMode}` is wired but all screens use `StyleSheet` with hardcoded light hex colors. Dark mode toggle in settings does nothing visible.
3. **`advanceNextDueDate` month-end edge case** — logic uses `Math.min(day, ...)` which appears correct (Jan 31 → Feb 28, not Mar 3) but is completely untested.
4. **`victory-native` / `PolarChart`** — package is listed as a shortcut stub (`shortcut: victory-native not installed`). The import at `insights.tsx` line 7 will cause a Metro bundler crash until the package is installed with `--legacy-peer-deps`.
5. **Settings has no sign-out / sign-in flow** — `runFullBackup` requires an active session but the UI has no way to authenticate. Tapping "Backup Now" with no session will throw synchronously with no catch in the Settings screen's `handleBackup`.
