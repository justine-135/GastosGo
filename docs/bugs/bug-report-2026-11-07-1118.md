# Bug Report — 2026-11-07 11:18

**Session:** Full E2E Maestro run (all 4 flows) — after `_layout.tsx` blank-screen fix

## Bugs Found

| # | Screen / Flow | Severity | Description | Repro Steps |
|---|---------------|----------|-------------|-------------|
| 1 | App launch / all flows | High | **Blank white screen on launch (regression)** — `_layout.tsx` added `isAuthChecking` state that blocks render with `return null`. If `SecureStore.getItemAsync` throws (common after Maestro `clearState` wipes Android Keystore state) or `navState?.key` never becomes truthy, `setIsAuthChecking(false)` is never called and the app shows a permanent blank screen. **Fixed in this session** by adding `.catch(() => setIsAuthChecking(false))` and a 3-second timeout fallback. | Cold-start app after `clearState` (or fresh install). App stays blank indefinitely. |
| 2 | Expenses tab | Med | **Category filter chips render as full-height boxes** — On the Expenses screen, the category filter row (All / Food chips) renders as very tall vertical boxes consuming most of the screen height rather than compact horizontal scrollable chips. The list area behind them is not visible until scrolling past the chip row. | Navigate to Expenses tab with at least one expense. Observe the "All" and category chips — they fill ~60% of screen height. |
| 3 | Add Expense modal | Low | **Merchant field not reachable via label tap** — `tapOn: "MERCHANT (OPTIONAL)"` targets the section label text, not the TextInput below it. `inputText` after this tap goes nowhere, so the merchant name is never entered. After saving, the transaction shows the category name instead of the merchant. | Open Add Expense modal → tap the "MERCHANT (OPTIONAL)" label text → type any text → save. Transaction appears with category name, not the typed merchant. |
| 4 | Add Expense modal | Low | **Amount field shows integer without decimal formatting** — When typing "250" into the amount field, the modal displays `250` rather than `250.00`. PRD spec cites `₱129.75` as the expected display format; the decimal component is absent until a decimal point is explicitly typed. | Open Add Expense → type `250` via keyboard. Amount displays `250` not `250.00`. |
